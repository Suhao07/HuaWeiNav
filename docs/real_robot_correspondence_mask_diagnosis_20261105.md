## 因果判断

- **已证实的历史问题**：同一 UID 内有椅子与邻接物的观测，椅子证据也跨两个 UID。源关联重放的目标 183 条观测分配复现，说明问题早于本次豆包调用。完整重放不是全局完全一致（5382 条中有 1 条非目标差异）。
- 原 `frame1365:detection2` 桌边种子后来吸收椅子观测，再按双向表面覆盖 0.934/0.969 与主椅簇合并；原另一候选与主簇的覆盖 0.550/0.901 未通过双向阈值。不能仅凭种子标签指控最终重复合并规则，也不能靠降阈值合并两个 UID。
- **已证实的模型解释问题**：8 条冲突中至少上述 3 条的可见内容与模型总体“不同物体”理由不符。标签诱导、独立黑白掩码对齐困难、跨 UID 推理混淆都是可能机制；一次响应无法区分其因果占比。
- 即使纠正这 3 条，历史混合与跨 UID 椅子碎片仍然存在。因此 `fragments`/不绑定仍是合理的保守结果，不能以产出 `unique` 作为通过标准。

## 最小修复与验证

仅修复对应模块的视觉输入表达：每条历史证据由“全图 RGB + 独立黑白掩码”改为“全图 RGB + 精确掩码内 RGB 紧裁剪”。非掩码像素填灰；保留原像素颜色、不缩放、保留孔洞；随请求记录裁剪坐标和派生 PNG SHA256。提示明确局部不等于整物体、检测标签可能错误。版本为 `2026-11-05-masked-rgb`。原始输入哈希不变。

未修改关联阈值、历史 UID、历史地图或绑定准入，也未按人工审阅删除观测。这是已定位输入歧义的最小修复；**历史混合问题仍未修复**。后续若修融合，应在原观测→关联分数→吸收事件上验证防止不同物体进入同簇的规则，并同时检查不会把真实椅背/椅身分得更碎，不能按物类白名单修这一个场景。

验证：33 项测试通过（对应入口 + SDK 请求路径），包括原像素/孔洞/非零掩码语义、空或错尺寸掩码拒绝、哈希保护、旧会话拒绝、非唯一结果不绑定。真实冻结包 11 条观测离线装配通过，LLM_OFFLINE 下不访问客户端，结果保持 insufficient。默认 Python 的 pytest 曾被全局 dash/flask 插件导入错误阻断；使用既有 conceptgraph 环境并禁用自动插件后完成测试。

本轮外部请求 0、绑定写入 0；无机器人操作、未部署本地修复。**尚未证明新表达让豆包更准确**；需要另一次明确授权的同包对照调用才能验证模型效果。那也不等于当前会话的真实绑定验收。
